# 扫码凭据修复

登录方式仍为官方扫码授权。不要把其他工具正在使用的 RT 拷进来共同刷新。

已覆盖的回归问题：

- 同一 `sid` / `sub` 的旧明文 RT 重导入时，不得覆盖已轮换的新凭据。
- 刷新响应的 RT 到期时间（绝对时间或相对秒数）优先于旧登录响应；导出给客户端时使用当前到期时间。
- 网络错误、429、5xx 不持久化为“必须重新登录”；明确认证拒绝仍保留失败信息。

## 只恢复一个失效账号

```powershell
cargo run -p wb-switch-core --example repair_qr_login -- ACCOUNT_ID
```

`ACCOUNT_ID` 来自本机账号列表，不能填写手机号或字面占位符。

该入口仅接收已标记失效的国内版账号，输出官方授权链接。用户仍通过原扫码方式授权：

1. 新凭据写入 `~/.wb-switch/repair-candidates/<随机标识>/` 隔离目录。
2. 校验扫码得到的 UID 与指定账号一致。
3. 验证成长接口、刷新 RT，再验证一次成长接口。
4. 持有账号库锁，确认原账号仍失效且凭据未被别的进程修改，才替换该账号；保留原 ID、备注和创建时间。

不关闭客户端，不切换当前 CLI 账号，不替换其他账号。扫错账号、验证失败或并发更新时拒绝覆盖。候选目录包含凭据，按账号库同等级别保护，不上传或提交 Git。

这些回归缺陷可在离线测试中复现；它们是否触发了某次具体服务端会话失效，需要当时的记录证明。旧 RT 被服务端拒绝时，代码修复本身不代表登录已恢复，应以扫码后实际业务请求和跨次续期结果验收。
